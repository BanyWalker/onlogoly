# 数据库脚本

设计以 [TDD-OM-002 v1.2.4](../../曦元本体平台SDD开发/02_技术设计/TDD-OM-002_对象建模工作台详细设计.md)（Draft，唯一事实源；TDD-OM-001 主稿已不存在、其结论已被吸收）与 ADR-OM-001 v0.5.0（Proposed，PostgreSQL 为目标态方向）为据，上游 SRS-OM-001 v1.7.0 已批准。**首期持久化为本地 JSON 文件（TDD-OM-002 §10，用户确认），本目录暂不实施业务迁移**；未来数据库化时的表结构与迁移路径见 TDD-OM-002 §10.5（对象定义、领域、历史/引用、布局、身份；规则/案例/术语判定的原设计保留，不展开检查/报告/核查表设计）。

## 执行顺序

1. bootstrap/：建库、数据库角色和需要的扩展；环境先核查，不假定可清库。
2. migrations/：按Flyway版本顺序执行不可变结构迁移；实施时通过构建资源映射打包到后端，从同批schema生成jOOQ代码。
3. reference-data/：固定角色、状态等基础数据；账号凭据通过部署安全初始化提供。
4. 术语/模型定义通过业务保存契约进入数据库，同步写定义、修订和引用；术语判定/案例/样例由各自模块写自己的表并加入同一事务。不把所有业务表的写入集中 common；模型包导入属后续治理范围。

完整对象 JSON（TDD §5.8）从当前定义与布局一致快照组装，不作为第二份权威 JSON 入库。object_canvas_layout 归 modeling.object，节点/边首次建立、删除和目标变更随定义提交；纯坐标/标注位置更新只递增 layout_revision，不改 element.revision/content_seq。新领域在对象提交内登记/复用，同事务失败全部回滚。领域当前只展示与内联新增，专门修改/删除暂缓。

fixtures/仅放FIX-OM-001合成验收与性能数据，由测试装载器或服务契约初始化；专用历史反例装载不得开放给普通用户。scripts/存备份、还原、一致性核查及开发工具，不作为应用启动的隐式业务写入口。

运行账号对定义、案例、样例历史和术语判定仅 INSERT/SELECT。业务定义及投影修改遵守同一 workspace guard 事务，禁止 SQL 旁路造成不一致。删除使用墓碑保留历史与 id，派生索引可受控重建，不能据此改写主定义。复核记录、检查快照/报告后续再设计所有权和迁移。

已执行迁移不得修改，结构修正新增迁移。发布前验证备份还原，回退前核对旧代码与当前schemaVersion兼容；Flyway不提供本项目已验证的自动回退。密码、令牌和生产数据不得写入脚本。
